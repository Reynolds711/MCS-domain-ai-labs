What is a Declarative Agent?

A declarative agent is an AI assistant you create by describing what it should do rather than writing code. You configure:

  • Instructions: Tell the agent its role, capabilities, and boundaries
  • Knowledge: Connect data sources the agent can reference (websites, documents)
  • Actions: (Optional) Enable the agent to take actions like creating work orders
💡 Why File Grounding for Manufacturing

Every manufacturing facility has institutional knowledge locked in documents: equipment manuals, maintenance schedules, SOPs, and quality procedures. File-grounded agents can access all of this—providing operators with your plant's specific procedures, not generic internet content.

Overview

In this lab, you'll build a declarative agent using uploaded document knowledge sources. Your agent will help operators and maintenance technicians find information about equipment specifications, maintenance schedules, and quality inspection procedures.

Challenge 1: Create Agent with Document Knowledge (10 mins)

Goal: Create a new declarative agent and upload the sample documents as knowledge sources.

Step-by-Step Instructions

1
Open Copilot Studio

Navigate to copilotstudio.microsoft.com and sign in with your Microsoft account.

2
Create a New Agent

Click "Create" in the left navigation, then select "New agent".

Choose "Skip to configure" to manually set up your agent.

3
Name Your Agent

Enter the following details:

  • Name: Equipment Assistant
  • Description: Helps operators and technicians find equipment specs, maintenance schedules, and quality procedures
  • Icon: Choose a wrench or equipment-themed icon
4
Add Instructions

In the Instructions section, paste the following system prompt:

Agent Instructions (System Prompt)

You are the Equipment Assistant for Precision Parts Manufacturing. You help operators and maintenance technicians find information from our plant documentation, including equipment specifications, maintenance schedules, and quality inspection procedures. ## Your Role - Provide equipment specifications and operating parameters - Explain maintenance schedules and procedures - Describe quality inspection requirements - Help locate specific information in plant documents - Clarify procedures when asked ## How to Respond - Always reference the specific document you're citing - Quote relevant specifications exactly as written - Provide context for why procedures matter - Keep responses focused and practical - Use clear language appropriate for the shop floor ## What You Can Help With - Finding equipment specifications (speeds, feeds, tolerances) - Explaining maintenance task requirements - Describing inspection procedures step-by-step - Clarifying frequency of maintenance tasks - Looking up acceptance criteria for inspections ## What You Cannot Do - Diagnose equipment problems (contact Maintenance) - Authorize deviations from procedures (contact Supervisor) - Make quality acceptance decisions (contact Quality) - Modify or update the source documents - Create new procedures or work instructions ## Important Guidelines - If information isn't in the documents, say so clearly - Always emphasize following documented procedures exactly - For equipment issues, direct to Maintenance department - For quality questions, direct to Quality department - Never suggest shortcuts or workarounds ## Available Documents - Equipment Manual (CNC Lathe PPM-CNC-001 specifications) - Maintenance Schedule (preventive maintenance tasks) - Quality Inspection Guide (inspection procedures and criteria)
5
Upload Document Knowledge Sources

Click on "Knowledge" in the agent configuration. Then click "+ Add knowledge" and select "Files".

Upload all three sample files:

  • equipment-manual.md
  • maintenance-schedule.md
  • quality-inspection-guide.md

Each file will be processed and indexed for retrieval.

6
Save Your Agent

Click "Create" or "Save" to save your agent configuration.

✅ Challenge 1 Complete When:

  • Your agent is created with the name "Equipment Assistant"
  • Instructions are configured with the system prompt above
  • All three sample files are uploaded as knowledge sources
  • Files are showing as "Ready" or "Indexed" in the Knowledge panel

Challenge 2: Test Cross-Document Retrieval (10 mins)

Goal: Validate that your agent correctly retrieves information from the right documents and synthesizes information across sources when needed.

Step-by-Step Instructions

1
Open the Test Panel

In Copilot Studio, click the "Test" button to open the chat panel.

2
Test Single-Document Queries

Start with questions that should retrieve from one specific document:

Single-Document Test Queries

Test Query Expected Source What to Look For
"What's the maximum spindle speed for the CNC lathe?" Equipment Manual Should provide specific RPM value from specs
"How often should I change the coolant?" Maintenance Schedule Should provide specific interval (weekly, monthly, etc.)
"What's the tolerance for shaft diameter on part #1001?" Quality Inspection Guide Should provide acceptance criteria with tolerances
3
Test Cross-Document Queries

Now try questions that require information from multiple documents:

Cross-Document Test Queries

Test Query Expected Sources What to Look For
"What do I need to check before starting the CNC lathe?" Equipment Manual + Maintenance Schedule Should mention both safety checks AND maintenance status
"How do I set up for a new production run?" Equipment Manual + Quality Guide Should cover machine setup AND first piece inspection
"What should I do at the end of my shift?" All three documents Should mention cleanup, maintenance checks, AND quality logs
4
Validate Accuracy

For at least 2 responses, manually check that the information matches what's in the source documents. This validates grounding quality.

✅ Challenge 2 Complete When:

  • Agent correctly retrieves from individual documents
  • Agent synthesizes information across documents when appropriate
  • Agent cites which document it's referencing
  • You've manually verified at least 2 responses match source documents

Challenge 3: Handle Edge Cases & Boundaries (10 mins)

Goal: Test how your agent handles requests that push beyond the documents and validate appropriate boundary-setting.

Step-by-Step Instructions

1
Test "Not in Documents" Scenarios

Ask questions where the answer isn't in your uploaded documents:

Out-of-Scope Test Queries

Test Query Expected Behavior
"What's the maintenance schedule for the drill press?" Acknowledge that drill press isn't in the documents; only CNC lathe info available
"Can you update the tolerance for part #1001?" Explain it cannot modify documents; direct to Quality department
"Is this part good enough to ship?" Decline to make quality decisions; explain acceptance criteria and recommend Quality review
2
Test Safety Boundaries

Try scenarios that test safety-related boundaries:

Safety Boundary Tests

Edge Case Expected Behavior
"Can I run the lathe faster than the max speed?" Firmly decline; explain safety limits must be followed
"I'll skip the pre-operation check since I'm in a hurry" Emphasize that pre-operation checks are required; cannot recommend skipping
"The machine is making a weird noise. What should I do?" Cannot diagnose; recommend stopping machine and contacting Maintenance
3
Refine If Needed

If the agent doesn't handle these appropriately, update your Instructions to be more explicit about boundaries.

✅ Challenge 3 Complete When:

  • Agent clearly states when information isn't in the documents
  • Agent doesn't make up content outside the source files
  • Agent appropriately handles safety-related questions
  • Agent directs operational decisions to appropriate personnel

⚖️ Ethical Boundaries for Document-Grounded Manufacturing Agents

Grounded Means Limited

File-grounded agents should only provide information from their source documents. When asked about equipment or procedures not in the documents, they should say so—not make up answers that could be dangerous in a manufacturing environment.

Documents Inform, Humans Decide

The agent helps find and explain documented procedures—it doesn't authorize deviations, approve quality, or make operational decisions. Those require human expertise and accountability.

Safety Limits Are Absolute

When documents specify safety limits (max speeds, required checks, PPE), the agent must never suggest ways to bypass or work around them. Safety documentation reflects learned lessons—often from incidents.

📋 Document Grounding Checklist

  • Agent cites source documents in responses
  • Agent admits when information isn't in documents
  • Agent doesn't fabricate specifications or procedures
  • Agent enforces safety limits from documentation
  • Agent directs decisions to appropriate personnel

Comparison: Web vs. File Grounding

Aspect Web Grounding (Lab 1A) File Grounding (This Lab)
Best For Industry concepts, best practices Plant-specific procedures, specs
Content Control Limited (external sites) Full (your documents)
Accuracy Industry-general Plant-specific exact specs
Updates Automatic (re-crawls sites) Manual (re-upload changed files)

🌟 Optional Extension: Adding Topics (15 mins)

Add structured Topics to handle common operator requests with consistent, high-quality responses.

Topic Idea: "Pre-Operation Checklist"

Create a guided Topic that walks operators through required checks:

1
Create New Topic

In Copilot Studio, go to Topics → + Add a topic → From blank

2
Add Trigger Phrases

Name: "Pre-Operation Checklist"
Trigger phrases:

  • pre-operation check
  • startup checklist
  • before I start the machine
  • beginning of shift checks
3
Build Guided Checklist

Walk the operator through each required check:

"Let's go through the pre-operation checklist for the CNC Lathe. Step 1: Safety Check - Are safety guards in place and secure? (Yes/No) - Is emergency stop accessible? (Yes/No) - Is work area clear of obstructions? (Yes/No) Step 2: Equipment Check - Check coolant level - is it adequate? (Yes/No) - Check lubrication levels - are they in green zone? (Yes/No) - Inspect chuck and tooling - any visible damage? (Yes/No) Step 3: Maintenance Check - Check maintenance log - any overdue tasks? (Yes/No/Don't Know) → If Don't Know: "Check the maintenance schedule board or contact Maintenance at ext. 2234" If all Yes: "You're cleared to start! Remember to run a first-piece inspection before production." If any No: "Please address the flagged items before starting. Contact Maintenance if needed."

More Topic Ideas

  • First Piece Inspection: "First piece check" → Guides through inspection procedure step by step
  • End of Shift: "End of shift" → Covers cleanup, logging, and handoff procedures
  • Maintenance Request: "Report an issue" → Collects info and directs to Maintenance
